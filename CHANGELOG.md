# Changelog

All notable changes to the GlimStone design language are documented here. Versioned independently of any app that adopts it.

## Unreleased

### ✨ Added

- A fifth motion-engine keyframe, `glim-shake` (`docs/design-language.md`, "The motion engine"; `reference/tokens.css`): a control refusing an action shakes instead of just silently reverting. A toggle switched on then rejected by a real backend precondition (no SSH configured for a feature that needs it, say) needs to visibly say "that didn't work," not just quietly snap back while the real explanation sits in a toast the eye may not be on yet. 360ms `ease-in-out` one-shot `translateX` oscillation, decaying `±4px → ±4px → ±2px → ±2px` through the middle four keyframes back to 0; under `prefers-reduced-motion: reduce` it swaps for a brief opacity pulse instead of nothing, matching every other entrance's reduced-motion substitution. Documented the one real implementation gotcha up front rather than letting it get rediscovered per adopting app: replaying the shake on a repeated identical failure needs a fresh DOM node (key the shaking element on an incrementing per-instance failure counter), not a re-toggled class — an animation already at rest doesn't restart just because its class briefly leaves and returns within the same frame. Named for the gesture, not the first control it shipped on — reach for it anywhere an optimistic UI update has to be undone (a rejected toggle, a form field failing server-side validation after looking locally valid, a drag snapping back because the drop target refused it), not just toggles. First implemented in BombVault.

## 1.0.0 — 2026-08-21

The first public release of the design language: the full rule set, the reference tokens, and the componentry it took to keep BombVault, KnightLoader, TrickWork and every app since consistent with each other.

### ✨ Added

- Initial repository. Extracted the design language out of KnightLoader, where it had lived as `docs/design-language.md` + `web/src/index.css` + `web/src/lib/appearance.ts` since 2026-08-06, and merged it with the more complete rule set that had since evolved in the vault-only style guide (rules 9 through 19: three-way colour modes, section badges, content-edge alignment, everything-clickable-is-a-badge, borderless form fields, the window contract, hover-survives-hover, no forced `display`, replace-not-persuade, shared-box grouping — none of which had made it back into the KnightLoader repo copy).
- [`docs/design-language.md`](docs/design-language.md) — the full spec, all nineteen rules, the palette, the name's etymology, componentry (info bubble, horizontal selector, switches, the reveal eye, foreign-host-UI plugins), the two user-owned axes, the rainbow colour-mode system and its three known traps, the token contract, and the adoption steps.
- [`reference/tokens.css`](reference/tokens.css) — framework-free reference tokens and utility classes.
- [`reference/tailwind-theme.css`](reference/tailwind-theme.css) — the optional Tailwind v4 `@theme` mapping layer, split out from the framework-free tokens so a non-Tailwind app can skip it entirely.
- [`reference/appearance.ts`](reference/appearance.ts) — the shape/accent/rainbow logic, genericised from KnightLoader's copy (cache key, code comments) so it drops into any adopting app unchanged.
- **The user-owned axes, expanded from two to four.** Theme (light/dark/system, default system) and language now get the same explicit governance as shape and accent: applied once at the app root, never by the page that edits them. The accent's default — Sunflower gold `#FCC419` on first install, before anyone touches the picker — is now stated in prose, not just implied by a table annotation.
- **Right-to-left languages**, promoted from a single aside on the horizontal selector to its own section: logical properties handle most of the mirroring for free, but technical content (paths, URLs, filenames, log lines) stays pinned `dir="ltr"` + `text-align: start` regardless of page direction, and directional icons mirror while symmetric ones don't.
- **Non-Latin scripts**: how the font stack's fallback actually works (per-glyph, not a fixed named list), plus two concrete fixes — CJK letter-spacing reset (the base tightening reads as crowding on full-width glyphs) and a note that `.glim-num`'s tabular-figure feature is a Latin-digit convention with no defined effect on other numeral systems.
- A banner (`.github/assets/`): a running-bond brick wall with one gold-lit block, drawn from a real hand-authored master SVG and recoloured programmatically — the name's own opening line, "a small light in dark masonry," drawn literally. The gold block is the constant core across both theme variants; only the stone tone swaps to keep reading against its background — the same pattern every other logo pair in this house style follows.
- **Named the two existing mechanisms and added a third.** Shape was already called "the shape engine" in passing; formalised that, and named the theme/accent/rainbow mechanism **the colour engine** (one mechanism, three inputs, all resolving to the same handful of tokens). Added **the motion engine** as its own section — it existed as CSS (four keyframes, a `prefers-reduced-motion` block, rule 10) but was never documented as a system with its own timing rationale.
- A short "engines we don't have" note explaining why browser-engine differences (Chromium/Gecko/WebKit) stay out of scope: everything GlimStone does runs through standard CSS media queries and custom properties, which behave identically across engines — engine-specific branching is an application concern, not a design-language one.
- **Repository made public**, with the license and funding files that implies: AGPL-3.0 (name and branding reserved, matching every other own-named product repo), `FUNDING.yml`, a License badge, and the Buy Me a Coffee button top and bottom.
- **Chosen mark: one lit block in a running-bond brick wall** — literal to this document's own opening line. An earlier placeholder (a synthesised 3x3 grid, drafted before a real hand-drawn logo existed, alongside two other concepts — a seal with a sunburst was the other finalist) was later replaced by the user's own real design.
- **Five new sections extracted from real, working code rather than invented:** Badges (four shape registers, named size stages with one canonical source, the pixel-parity-across-element-types discipline, the `font-size: 0` + `vertical-align: middle` trap — generalised from CannonadeCommand's production badge system, previously only in its app-specific subnote), Toasts (duration, stacking, hover-pauses-and-preserves-remaining-time, severity-filtered quiet mode, toast-vs-dedicated-surface judgement — from KnightLoader's `lib/toast.tsx`), Empty states (the shared `EmptyState` shape, and the zero-items-vs-zero-matches copy distinction), Destructive and confirmable actions (reversible fires immediately, irreversible gets a real modal stating exact stakes, the control is always the fault colour), and Charts, marked provisional since only one example (a speed graph) currently exists.
- A short technique note in `reference/tokens.css`: cap a pill radius against the element's own height (`min(var(--radius-pill), 50%)`) rather than applying the raw token, so a compact badge doesn't over-round into a lozenge. (Later found to be backwards — see Fixed, below.)
- **The type scale**, extracted now that the underlying app is actually consistent: four repeatable steps (20px heading, 14px body, 12px dense, 11px caption — the last covering three treatments of one size, not three sizes), plus an explicit note that a page's one hero figure and any brand-wordmark instance are deliberately *not* part of the scale. Not named an engine: unlike shape/colour/motion, nothing varies it — it's a fixed reference table, the same category as the palette.
- `--text-heading`/`--text-body`/`--text-dense`/`--text-caption` tokens in `reference/tokens.css`; `.glim-eyebrow` and `.glim-bubble` now read `var(--text-caption)` instead of their old separate 10px/11.5px literals.
- Rule 14 gains a scroll-to-cycle behaviour for `<select>` elements: a new [`reference/selectScroll.ts`](reference/selectScroll.ts) (`enableSelectScroll()` / `enableSelectScrollForAll()`) lets a closed dropdown answer the mouse wheel directly, stepping `selectedIndex` and firing a real `change` event without ever opening the native dropdown. The platform default only wires the wheel up once a `<select>` is already open; this closes that gap for values people reach for constantly (a font, a preset, a language) so they don't cost a click first. Framework-free, idempotent, dependency-free like `appearance.ts`. Requested while building a character-set/font-heavy settings surface in an adopting app, where scrolling through options one at a time is the natural gesture.
- A new "The sidebar" section documents the persistent left-rail navigation already live in BombVault and KnightLoader (brand mark top, vertical icon+label destination list, Settings pinned at the bottom below a spacer, `--carbon-sidebar` as its own surface token, real `aria-current="page"` navigation semantics rather than the ARIA tabs pattern the horizontal selector uses) as GlimStone's own canonical multi-destination pattern for the first time — it existed in two apps' code but nowhere in the design language itself. Also documents the sanctioned lightweight alternative for a genuinely simple, single-workspace app: a small square Settings badge (gear glyph, top-right, `--radius-control` not the pill) instead of a full rail, opening Settings as its own full-page view with no preview or working cards behind it.
- New rule: version numbers belong in Settings, never in a persistent footer — a version string in permanent page chrome is read once and then costs a line forever, the same objection rule 8 already makes about explanatory prose sitting under every control.
- The Language axis (under "The user-owned axes") now documents flag-emoji-prefixed options for the language `<select>` — a new [`reference/flagEmoji.ts`](reference/flagEmoji.ts) (`flagEmoji(isoCode)`) converts an ISO 3166-1 alpha-2 code to its regional-indicator flag emoji by string concatenation alone, so a native `<option>` (which can only ever hold plain text, never an image or CSS background) can still show a flag next to each language name without forcing a custom-built dropdown just to render one. Notes that a component-framework app that already isn't using a native select for other reasons may reasonably build a custom dropdown with a real flag-icon sprite library instead — this is the plain-`<select>`-compatible default, not a mandate to avoid a fancier approach elsewhere.
- New [`reference/colorPicker.ts`](reference/colorPicker.ts) is a saturation/value square + hue bar — real DOM the app owns, extracted from CannonadeCommand's own `inlinePicker()`. `.glim-picker`/`.glim-picker-sv`/`.glim-picker-hue` in `reference/tokens.css` give it the shared look. `openColorPickerPopover(trigger, hex, onChange)` wraps it in a floating `.glim-picker-popover` anchored to a trigger element (closes on outside click, Escape, scroll or resize) — the recommended default for a compact settings card, where embedding the picker permanently grows the card every time one is added. The bare `colorPicker()` (no popover) is still there for a page with genuinely dedicated, permanent space for exactly one control. The popover also carries a paired `.glim-picker-hex` text field (CannonadeCommand's own `cc-set-hexin`) — bidirectionally synced, so a value can be typed or read back exactly, not only dragged.
- New `.glim-tint-hover` on the colour engine: the same rest-quiet/hover-reveals wash `reactive` mode already gave the whole app, now available per-element regardless of the user's own on/reactive setting — for a row of equal-weight ACTIONS (not a persistent selection), permanently washing every member under plain `on` competes with the page instead of accenting it. Its own reveal now reads the stronger `--item-hue-badge` tier (50%), not the list-row `--item-hue-wash` (16%) — a hover reveal is a deliberate, momentary state closer to a badge's own "clearly coloured" bar than a list's "don't overwhelm a column of these" one.
- New `.glim-tint-badge` on the colour engine, alongside a new `--item-hue-badge` tier (50% alpha) in `hueVars()`: for a compact circular badge that needs colour AT REST because it has no checked/active state of its own to fall back on.
- The Language axis's custom-listbox escape hatch (design-language.md, "The user-owned axes" > Language) now documents a follow-up fix for the Windows flag-rendering gap it already accepted as expected: an app that upgraded to a custom listbox (real page DOM, not a native `<select>`) can layer in [`noto-color-emoji-flags`](https://www.npmjs.com/package/noto-color-emoji-flags) (OFL-1.1, a ~800KB COLR-vector subset of Noto Color Emoji containing only flag glyphs) scoped to just the flag span, so Windows shows real pictorial flags too instead of the two-letter fallback tag. Deliberately not Twemoji's own country-flags subset — Twemoji is CC-BY 4.0, which fails the OFL-only asset rule. `reference/flagEmoji.ts`'s own comment updated to point here; the function's output itself (plain regional-indicator codepoints) is unchanged — this is a presentation-layer fix, not a behavioural one. First adopted in TrickWork.

### 🎨 Design

- This is the first version to carry a token reference table and an explicit utility-class list (`.glim-hue-icon`, `.glim-tint`, `.glim-page-enter`, `.glim-toast`, `.glim-fade`, `.glim-live`) alongside the rules — previously only implicit in the CSS itself.
- Dropped the "private, internal" framing from the README; GlimStone is published for reference and transparency, though still not positioned as a general-purpose design system seeking outside adopters.

### ⚡ Improved

- The sidebar's version-numbers rule is more specific: version numbers live at the very bottom of the Settings destination itself, outside every card — not inside whichever card happens to be last. Tucking it into one particular card made it read as that card's own property instead of the whole app's, and tied its position to wherever that card happens to land if Settings ever gains or reorders cards.
- The Accent axis gains a documented picker layout: presets, the custom colour input, and a reset badge all in **one row, all the same size** (the native colour input no longer reads as a mismatched rectangle glued on after circular swatches), reset pinned to the trailing edge as an icon badge, and every swatch in the row following the shape engine.
- The Language axis's flag-emoji-prefixed plain `<select>` is now explicitly the *default*, not a framework-gated mandate: any adopting app (framework or not) whose language field or option list still reads as cramped after reasonable padding may build a custom button+listbox dropdown instead — a native select's own field height and open-list row padding are effectively unstyleable, and a dozens-of-entries language list is exactly where that stops being cosmetic.
- Rule 13 (everything clickable is a badge) now says explicitly: a small, single-purpose action badge (copy, reset, undo) carries an icon, not a text label — the name lives in `title`/`aria-label` instead, matching how icon-only toggles already work. Primary, sentence-length actions ("Export settings") are unaffected.

### 🐛 Fixed

- `reference/tokens.css` was missing the base `body` rule (background, font stack, letter-spacing) and `* { box-sizing: border-box; }` entirely — dropped during the original extraction from KnightLoader's `index.css`. An app following the adoption steps literally would have gotten every component class but not the page-level defaults they assume.
- Generalised the few remaining named references to specific sibling apps (README opener, the info-bubble and horizontal-selector sections) — this document was already meant to be app-agnostic; the wording hadn't fully caught up.
- `.glim-live`'s pulse had no `prefers-reduced-motion` fallback at all — an infinite 2s animation is exactly the category that preference exists for, unlike the one-shot entrances that already degraded correctly. It now renders as a static, fully-opaque dot under reduced motion instead of continuing to pulse.
- [`reference/appearance.ts`](reference/appearance.ts) failed to typecheck under a consumer's stricter TypeScript settings (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`) — found while adopting GlimStone into a new strict-mode project. `rainbowAt()` now throws a descriptive error on the (practically unreachable, since `usablePalette()` never lets the palette go empty) case its indexed lookup can't statically prove is defined; `cacheAppearance()` now builds its cached payload with a conditional spread so an absent `rainbow` argument omits the key entirely instead of setting it to `undefined`. Both fixes preserve the exact same runtime behaviour — this is a type-only correctness fix for adopting apps that run with these stricter flags, not a behaviour change.
- [`reference/tokens.css`](reference/tokens.css) never actually implemented the documented "theme defaults to system" behaviour — `docs/design-language.md` states that an unset `data-theme` "follows the OS via `prefers-color-scheme`", but the stylesheet had no `@media (prefers-color-scheme: light)` block at all: the bare `:root` unconditionally applied the dark palette, so any adopting app that never explicitly sets `data-theme` opened dark regardless of the OS's light preference — the exact "opened dark on a light-mode OS nobody asked for" mistake the design language itself warns against. Added the missing media-query tier (`:root:not([data-theme="dark"])` under `@media (prefers-color-scheme: light)`, mirroring the same token values as `[data-theme="light"]`), so an unset theme now genuinely follows the OS in both directions, and an explicit `data-theme="light"`/`"dark"` override still wins regardless of OS preference. Found while wiring a full appearance-settings panel (shape/accent/theme pickers) into a new adopting app.
- The flag-emoji rule overclaimed "renders as a real flag glyph on every modern OS" — verified on Windows and that's wrong: Windows renders the same regional-indicator codepoints as a compact two-letter tag instead of a pictorial flag, a deliberate long-standing Microsoft emoji-font policy, not a rendering bug. macOS, Linux, iOS and Android do show the actual flag. Corrected the claim in both `docs/design-language.md` and `reference/flagEmoji.ts`'s own comment — the mechanism and the recommendation are unchanged, only the "every OS" wording was inaccurate.
- The rainbow mode's active-row highlight silently collapsed to the same flat wash as every other row, in both `on` and `reactive` mode, because `.glim-tint`'s own box-shadow declaration has higher CSS specificity than a typical single-class `.active`-style app rule and always won the cascade — an adopting app's own "this one is selected" class needs to ALSO carry the shared `.glim-active` marker, not just its own app-specific equivalent, for `tokens.css`'s composition rule to engage at all. `[data-rainbow] .glim-tint.glim-active` now covers both `on` and `reactive` (the previous fix, in an earlier reactive-mode pass, only generalised to the mode it happened to be tested against). Found via a real adopting app (TrickWork) whose queue never carried `.glim-active` on its own active row.
- The wash opacity (7%) shipped in the first version drew three independent "the mode does nothing when I turn it on" reports from the same adopting app before anyone measured the actual rendered colour rather than eyeballing it — it was applying correctly the whole time, just under the threshold a person registers as change. Raised to 16% (the selected-row soft tint: 14% → 22%).
- `.glim-bubble` previously had its own bespoke, JS-free styling (no arrow, no viewport clamping, no flip) — visibly inconsistent against a sibling app's own tooltip system built on the real thing. It now IS the real thing: same engine, same look, matching CannonadeCommand's reference exactly.
- The accent-row rule mandated a native `<input type="color">` sized like the preset swatches. That hands control to a browser/OS surface entirely outside the page — a genuinely separate top-level window on some setups, not an inline popover — directly contradicting a standing preference from CannonadeCommand's own build ("ich will das Farbwählfeld fest integriert") and unverifiable in automated testing besides. The picker section now documents ONE layout: every custom colour value (a single accent, or one of a palette's several positions) gets the same trigger — a flat swatch, same size as the presets beside it — that opens the shared popover pre-synced to its value.
- Rainbow's own docs never said the mode has to cover more than the first list it looked like an obvious fit for — an adopting app that wired only its download queue implemented "colours one list," not "rainbow mode," and kept drawing "it doesn't apply" reports no matter how many times that one queue's own mechanics were fixed. New fifth trap: `rainbowColor(i)`/`hueVars()` are already general-purpose: walk every genuine equal-member set in the app (segmented-control segments, icon toggles, anything that isn't the only one of its kind on the page) and wire each one.
- An icon-only badge that owns a rainbow position colours its own background (`.glim-hue` + `.glim-tint`/`.glim-tint-hover`), NOT its glyph — an earlier revision of this rule additionally recoloured the glyph via `.glim-hue-icon`, which read as one colour too many once a real adopting app tried it. `.glim-hue-icon` is still available, but only for a genuinely backgroundless glyph with nothing behind it to wash — not the default pairing for a real badge.
- A real TOGGLE badge (a genuine checked/unchecked state of its own) went through two rounds of idle-background washing (`.glim-tint`, then the stronger `.glim-tint-badge`) and a real adopting app rejected both: "die iconbadges sollen nicht eingefärbt sein und erst wenn man sie klickt. diese halb abgedunkelt eingefärbt sein gefällt mir nicht." The correct behaviour needed no new mechanism — `.glim-hue` alone (unconditional) plus the component's own checked-state fill (`background-color: var(--accent)`) already means nothing shows at rest and the position colour fills solid once checked. `.glim-tint-badge` is still real, just not the default for a toggle — reach for it on a badge with no checked state to fall back on. A badge with no persisted state at all (a momentary action — undo, redo, zoom) doesn't own a rainbow position, full stop: there's no "clicked and stays that way" moment for a fill to attach to, so wiring it in just means faking a rest colour again.
- The horizontal selector's own rainbow behaviour was never specified, so an adopting app washed every segment at rest the same way a list row does — noisy, since the selector's own fill already says which one is picked. Documented: only the SELECTED segment owns a position; inactive segments get neither `.glim-hue` nor `.glim-tint` at all.
- `border-radius: min(var(--radius-pill), 50%)` was documented as the fix for a compact badge over-rounding into a "pointed lozenge." It's the opposite: `50%` resolves per-AXIS (of width, of height) *before* the border-radius overflow algorithm runs, so on any non-square element it hard-codes two different corner radii up front and renders as a visible ellipse, not a pill — confirmed on a live 220×120 test box, an ellipse with the guard, a correct stadium without it. The raw token alone (`border-radius: var(--radius-pill)`) already renders correctly on ANY box, square or not — the browser's own corner-overflow algorithm scales all four corners down together to fit, with no capping needed. Docs and `reference/tokens.css` corrected; never write the `min(…, 50%)` guard, on badges or anywhere else.
- Cross-app info-bubble standardisation: BombVault's shipped `InfoBubble`/`.glim-bubble` is now the anointed reference implementation for the shared tooltip/info-bubble engine, and this repo's own copy had drifted from it in several real ways — one of them a genuine accessibility regression, not a style preference. `.glim-info-icon:focus-visible` set `outline: none`, actively removing the only visual signal a keyboard user had that the trigger was focused (opacity `.8 → 1` reads identically to plain hover, so it isn't a substitute). Split into its own rule with a real `outline: 2px solid var(--focus-ring); outline-offset: 2px` — the exact treatment every ordinary button and link already gets from this file's base `:focus-visible` rule — plus a new `border-radius: var(--radius-pill)` on the icon itself so that ring traces a circle around the glyph instead of a square. Documented in `docs/design-language.md` as the design language's one deliberate, sole exception to rule 5 ("hierarchy from type and colour, never borders"), stated in both rule 5 and the tooltip section, cross-referencing each other rather than duplicating the reasoning: mouse/hover interaction never shows a border, only keyboard focus does.
- `reference/tokens.css`'s `.glim-bubble` had drifted from its own recipe on five separate properties, verified against BombVault's real, shipped CSS: `background-color` was the WELL tone (`--carbon-surface2`) instead of the one raised surface every other card-like element reads (`--carbon-surface`) — a floating bubble is a card, not a sunken well. `box-shadow` was a bespoke flat `0 8px 24px rgba(0,0,0,.55)` with no hairline, instead of this file's own `var(--elevation), var(--hairline)` pair — the same recipe `.glim-card`/`.glim-toast` already use — so the bubble was the one surface in the whole language missing its top-light hairline. `padding` was `9px 12px`, corrected to a tighter `7px 10px`. `font-size` was a hardcoded `12.5px` that directly contradicted this same file's own type-scale comment three lines above it (which already claimed the info bubble's text was one of the three treatments `--text-caption` covers) — it now actually reads `var(--text-caption)` (11px), so the comment stops lying about the rule beneath it. `white-space` was `pre-line` (preserves literal `\n`s), corrected to `normal` — every real tip is a single wrapped sentence, not a multi-line block. `border-radius` simplified from a `min(var(--radius-control), 10px)` guard to the plain token — the two have never actually differed under any of the three shipped shapes, so the guard was inert. `.glim-bubble::before`'s and `.glim-bubble--above::before`'s arrow `border-color` now match the corrected background so the arrow still reads as part of the same shape it points from.
- Resolved a standing internal contradiction spanning `docs/design-language.md`, `reference/tokens.css` and `reference/tooltip.ts`: the motion-engine section always said the info bubble gets a 110ms fade, while the tooltip section claimed the opposite ("no transition — an instant display toggle") and the shared engine's own bubble element never actually carried the `.glim-fade` class needed to animate at all — so in production it really was instant, for a different reason than either doc passage gave. `tooltip.ts`'s `bubbleEl()` now applies `glim-fade` to the shared bubble (a CSS animation replays automatically when an element re-enters rendering after `display: none`, so no other change was needed); the tooltip section's prose now agrees with the motion-engine section instead of contradicting it, and states that closing has no fade (asymmetric on purpose — a hover-driven aid should vanish the instant the hover ends).
- `wireTooltips()` had no Escape handler at all — the only way to dismiss an open bubble by keyboard was to blur the trigger, which also gives up your place on the page. Escape now hides the bubble without moving focus, matching BombVault's own `InfoBubble` component.
- `infoIcon()`'s SVG glyph corrected to the exact markup BombVault ships: outer ring `r7.1`/`stroke-width 1.2` → `r7`/`1.3`; dot `r1.05` at `cy4.7` → `r0.9` at `cy4.6`; the stem changed from a filled rounded rect (`rect x7.05 y6.8 width1.9 height5 rx.95`) to a round-capped stroked path (`M8 7v4.4`, `stroke-width 1.3`, `stroke-linecap round`) — same three-piece "i" (ring, dot, stem), the real production numbers instead of an approximation of them.
